# State Machines

State machines are a strong fit for FTC because many robot behaviors move between a few distinct modes. Each mode has a clear job, and the transitions are easier to debug than a giant chain of conditions.

## FTC example

```java
switch (intakeState) {
    case OFF -> stopIntake();
    case INTAKING -> runIntake();
    case HOLDING -> holdGamePiece();
}
```

## Common mistakes

- Hiding too much logic inside one state.
- Making transitions unclear.
- Using state machines for problems that are already simpler than they look.

## FTC connection

State machines are useful for intakes, arms, elevators, and autonomous routines.
