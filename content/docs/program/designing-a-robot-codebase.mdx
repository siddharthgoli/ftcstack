# Designing a Robot Codebase

A good FTC codebase separates responsibilities so students can work on different robot systems without creating chaos. The goal is to make the robot easier to change, test, and understand.

## Core goals

- Keep hardware details close to hardware code.
- Keep high-level robot decisions separate from motor commands.
- Make the codebase readable for new team members.
- Avoid duplication across TeleOp and Autonomous.

## FTC example

Think in layers: input, robot logic, and hardware output. That makes it easier to test each layer separately.

## Common mistakes

- Putting everything in one OpMode.
- Copying drive logic into multiple files.
- Building code around one student instead of the team.

## What good looks like

When the robot needs a change, the team knows exactly which file or subsystem to touch.
