# Best Practices

Competitive FTC software should be readable, testable, and safe to modify. The best practice is not maximal complexity; it is predictable behavior and clear ownership.

## Rules of thumb

- Keep changes small.
- Prefer explicit state over hidden side effects.
- Test on the robot as soon as possible.
- Log the data you will actually need when things fail.

## Common mistakes

- Premature abstraction.
- Copying code instead of extracting a shared helper.
- Waiting until competition day to understand how a feature behaves.

## FTC connection

The best codebase is the one the whole team can safely evolve during the season.
