# Naming Conventions

Names should explain what the code does, not just how it is implemented. Clear names make team code faster to read during build sessions and competition repairs.

## Good names

- `intakeState`
- `drivePower`
- `targetHeading`
- `isArmReady`

## Common mistakes

- Using one-letter names in production code.
- Naming classes after temporary implementation details.
- Mixing abbreviations that only one student understands.

## FTC connection

Good naming makes telemetry, debugging, and code review much easier when the team is under time pressure.
