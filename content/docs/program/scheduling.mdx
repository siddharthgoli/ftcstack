# Scheduling

Scheduling is how a robot decides what work happens now, what waits, and what gets interrupted. Good scheduling keeps robot behavior predictable under driver pressure.

## FTC example

If the driver asks for a new arm action while the previous one is still running, the code should know whether to replace, queue, or ignore it.

## Common mistakes

- Letting every part of the robot run independently without coordination.
- Starting actions without a stop condition.
- Hiding the scheduler inside too many layers.

## FTC connection

Scheduling becomes important when TeleOp and Autonomous both need multiple systems to cooperate.
