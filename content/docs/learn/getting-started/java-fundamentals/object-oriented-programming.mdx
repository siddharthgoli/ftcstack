# Object-Oriented Programming

Object-oriented programming helps a team divide robot software into clear responsibilities. In FTC, this usually means separating subsystems, actions, and helper classes.

## Main ideas

- Encapsulation keeps hardware details inside one place.
- Abstraction hides the details of how something works.
- Reuse lets the team build on proven code.

## FTC example

Your drivetrain class should expose high-level actions like drive, stop, or turn instead of requiring every caller to manipulate motor power directly.

## Common mistakes

- Forcing inheritance where composition would be simpler.
- Designing classes around Java theory instead of robot behavior.
- Ignoring the team structure of the codebase.

## FTC connection

OOP is useful in FTC when it makes the robot easier to reason about, not when it adds layers for no reason.
